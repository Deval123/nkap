# Which of this repository's own rules are checked, and which are only written

`CONTRIBUTING.md` and `docs/conventions.md` state what a contributor and a maintainer must,
must never and always do. Some of those rules have something that fails when they are broken.
Some are left to a person on purpose. Some were written as if they were checked, and are not.
This page says which is which, one row per rule, so a reader can tell whether anything would
stop them from breaking it.

It is a **dated snapshot of those two files and nothing else**. A rule added to either file
after the date below has no row here, and this page cannot notice that; nothing pretends
otherwise. The ADRs, `SECURITY.md` and the README's promises are a later pass.

- **Read at:** commit `b1bc147` (2026-11-07). The workflow jobs, scripts, POMs and tests named
  below were opened and read at that commit. **Checked again at `0a651db` (2026-11-07):** only the
  rows and sentences listed under "Rows changed since" below. Every other row is as it was at
  `b1bc147` and was not reread, so none of them is vouched for at the later commit.
- **Rows changed since:** `core` has no dependencies (#276) and tags are annotated (#277) were
  instrumented after this page was read; their rows are updated and they have left the list of
  gaps below. Two rows were added for the dependency scan (#280), whose rules `CONTRIBUTING.md`
  states in a section written after this page was read, and the one about suppressions expiring
  was a gap until #282 closed it. A further row records that test scope is deliberately outside
  both scans. The row for money is an integer was rewritten for #285: its first clause is now
  instrumented, and the row says what is true of each of the other two. On 2026-11-07, at `0a651db`,

  follow-up to #288: it is red for HIGH or CRITICAL findings that have a fix, and findings with

- **Repository settings** (the `main` ruleset, merge methods, branch deletion, private
  vulnerability reporting) are not in any commit. They were read from the GitHub API on the same
  day, and again on 2026-11-07 (the ruleset, merge methods and branch deletion; not private
  vulnerability reporting). They can change without a pull request showing it.
- **"Deliberately not"** means the repository says so itself, or the rule is a judgment that no
  script could make. Where the repository records the choice, the row cites it; otherwise it is
  this page's reading, and a maintainer is free to disagree.
- **Prose that is not a rule** (for example "the hardest contribution to get merged is a change
  to `core`") has no row. Neither does a rule that is now history, such as the scope of v1.0.0.

The instruments are the eleven jobs in `.github/workflows/build.yml` (`build`, `demo`,
`integration-guide`, `release-tags`, `release-tag-guard`, `dco`, `suppression-expiry`,
`no-floating-point-money`, `image-scan-verdict`, `compose-project-names`, `helm`), the four jobs in `.github/workflows/release.yml`, the scripts under `.github/scripts/`,
the settings above, and tests in the reactor. The ruleset requires ten of those eleven before anything merges into `main`: every one
but `image-scan-verdict`, which is not required yet, so it reports and blocks nothing.

## What the gaps are, in the order they would be worth fixing

1. **Conversion outside a position account.** The one clause of rule 4 nothing checks, and no position account exists yet to check it against. Until one does, the rule is a sentence; a conversion would arrive as ordinary arithmetic on `Money`, and review is the only instrument.
2. **Assistant attribution and the English rule in commit messages.** A check beside `check-dco.sh` would catch the cases that reach git history, with the limit that it cannot reach pull requests, issues or comments.
3. **Module boundaries, and test scope for `nkap-conformance` and `nkap-test-support`.** They match today. A boundary nothing checks drifts without anyone choosing it, and the table already understates `server`.
4. **Branch name, `Closes #N`, `@DisplayName`.** Each is mechanical and unchecked, and each is cheap on its own.
5. **The by-hand release steps with a mechanical half:** the version a reader copies, the two independent versions, the API-compatibility rule, and reopening `-SNAPSHOT`. The procedure already gives the commands, and a release is rare, so these cost least when they are missed once.
6. **A new provider module with no conformance subclass or provider page.** Two adapters exist and both comply, so this waits for a third.
7. **ADR amendments.** The shape is mechanical and the content is judgment; the first half is worth checking only if amendments become frequent.
